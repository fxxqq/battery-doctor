问题不在指标

它给你 12 个数字，却答不出你唯一想问的那句话

「为什么用一会儿就关机」不是监控问题，是归因问题。而监控类工具的设计前提是「软件开着，人活着盯着」——恰恰和断电场景相反。

常规电池工具 监控

打开才采样，关掉即遗忘。第二天你看到的还是同一个百分比。

  • 只展示当下状态，不记录过程
  • 断电瞬间数据随内存一起消失
  • 指标各自独立，需要你自己连线
  • 结论是通用的「建议更换电池」
  • 看不见「接电却放电」这种矛盾

电池医生 取证

先假设它一定会断，所以每一秒都留了证据。

  • 每 5 秒写入 CSV，配心跳文件区分「没开机」与「断了电」
  • 重启后自动比对，指出哪一刻、掉了多少
  • 把供电矛盾、健康度、温度、限速放进同一条证据链
  • 给出有先后顺序的处置建议，不是一句话打发
  • 接电却以 −1107mA 放电，会直接标红
机制

三次落盘，换一个不可辩驳的结论

不猜、不推断，只做三件很笨但有效的事。

01

持续采样

每 5 秒读一次供电：电流方向、电压、温度、适配器握手状态、CPU 限速。macOS 走 ioreg，Windows 走 WMI 与 powercfg 报告。

02

立刻落盘

同时写 CSV 与心跳文件。正常退出会留标记，所以「程序没开」不会被误判成「断电」——这一步决定了证据干不干净。

03

重启后回现场

下次启动比对时间差与电量差：间隔超过 2 分钟、或跌幅超过 8%，判定为一次断电，并附上断电前最后一条完整采样。

六个方向

一次体检覆盖到能动手的地方

关机很少是单一原因。以下六项共用同一套采样与结论引擎，最后合成一句人话。

供电与电池

健康度、循环、逐节电压、接电却放电、适配器未握手。还会把「电芯学到的容量」和「系统报的容量」摆在一起——两者打架时，先别急着换电池。

异常关机取证

采样曲线 + 系统关机记录双向对照。Windows 直接读事件 41 / 6008，macOS 记录断电前后瞬间，两边都能给出准确时刻。

进程与负载

按 CPU 占用或按 CPU 周期数排序——周期数比百分比更接近真实耗电。持续高负载会推高温度，也是保护性断电的常见原因。

存储与清理

先扫出每一项占多少，勾选之后再确认一次才动手。缓存、日志、崩溃报告可以放心清；废纸篓与手机备份默认不勾，删掉的先落进废纸篓还能找回。

启动项

列出开机自启的每一项，可逐条禁用并保留还原路径。开机那几分钟的满载，是最容易触发瞬时掉电的窗口。

网络诊断与修复

八项分段检测：连上路由器、DNS 解析、外网连通分别判定。一键重置代理与 DNS、清缓存、重取 IP，说清是哪一段断了。

诊断工具箱

不止告诉你数据，还替你验一次

成熟监控软件把读数摆给你就走了。前四件是把读数变成行动的诊断，后两件是不用你操心就能享受到的保证。

校准向导

先记下校准前的容量，走完「放电—充满—静置」再回来复测，自动告诉你容量回升了多少。回升就是电量计记错了，一分钱不用花。

负载压降测试

安静 3 秒、满载 8 秒，同时记录电压电流，算出电压跌落与内阻。撑不住峰值功率的电池，就是这样被认出来的——这正是「一忙就关机」的物理原因。

一页纸送修单

命中哪几个故障码、断电前最后一刻的电压电流、按便宜到贵排列的处理顺序，全部写进一页 PDF。维修店说「电池老化」时，直接给他看这个。

充电养护

从采样历史算出你的充电习惯评分，再用 SMC 的 BCLM 键给充电器设一个硬件上限——插着电也最多充到 80%，电池不再停在满电。出远门改回 100% 就行。

不联网

采样从电池芯片直连硬盘，不经过网卡——拔掉 Wi-Fi 照样在记，记录里断掉的那截只可能是断电。没有服务器、没有账号、没有上报，你的使用数据不会离开这台机器。

不占宽带

后台流量 0 KB。唯一会发请求的是网络诊断，必须你亲手点，一次约 10 KB。日常不下载、不上传、不抢带宽，连后台常驻的内存都控制在百兆出头——这是一台老机器上跑的工具该有的样子。

数据去哪了

它不是「承诺不联网」，是结构上就联不了网

说「我们很重视隐私」太容易了。下面画的是数据实际走的路径——一条从芯片到硬盘的直线，出口只有你磁盘上那个 CSV 文件。没有服务器可以上传，因为没有服务器。

拔掉网线，它照样在记

数据源是 SMC 芯片里的硬件计数器，走 I/O Kit，不经过网卡。关掉 Wi-Fi 用一整天，时间戳依旧每 5 秒一条——记录里断掉的那一截，只可能是断电。

一条命令就能自证

终端执行 lsof -i -p $(pgrep -f BatteryDoctor)，返回空行，说明它一个连接都没建立。不用信我，你现在就能试。

唯一会发请求的地方

只有网络诊断页，而且必须你亲手点「开始检测」。三个空请求合计约 10 KB，只读 HTTP 状态码，不带参数、不带设备信息、不下载任何内容。

为了做到这一点，我砍掉了四样东西

这几样都算「现代软件标配」。砍掉它们，就不存在偷偷联网的可能。

  • 没有静默更新——检查更新要你亲手点；勾了「每周看一眼」也只是一个 2 KB 的版本号请求
  • 没有崩溃上报——崩了也不会把堆栈发出去
  • 没有账号与云同步——换机要自己拷一份 CSV
  • 没有使用统计——你打开多少次，我不知道
下载，然后拔掉网络再打开它 这句话既是使用方法，也是验收方法。

常见问题

你大概会先问这几件事

它会把我电脑上的数据传到哪儿吗？

不会。没有服务器，没有账号，没有崩溃上报。所有采样只写在本机：macOS 在 ~/Library/Logs/PowerWatch，Windows 在 %LOCALAPPDATA%\PowerWatch。断网也能完整使用。数据怎么走、怎么自己验证，见上面的路径图与验证命令。

能修好我的关机问题吗？

不能，诊断工具的天花板是定位。电池 BMS 或主板供电电路坏了，任何软件都只能指出来，修不了。它做的是把「该换哪个件」的证据摆在你面前，让你在维修店少被一句「电池老化」打发。

一直开着会不会更耗电？

每 5 秒一次 SMC / WMI 读取，CPU 占用可以忽略，采样文件超过 40 MB 会自动归档，最多占 40 MB 磁盘。如果你在意，可以随时暂停监控——已经落盘的记录不受影响。

macOS 版为什么有 28 MB？

因为它内嵌了一份 Python 运行时，换来的是「拖进应用程序就能双击打开」，不需要你装 Homebrew、pip 或任何环境。体积换省事，我认为值得。

Windows 版为什么给的是 zip 而不是 exe？

因为 exe 只能在 Windows 上构建（PyInstaller 不支持交叉编译）。zip 里带了「一键打包.bat」，双击一次就生成单文件 exe，之后可以随便分发。需要的那台电脑装一次 Python 即可。

为什么没有代码签名？

签名和公证需要每年付费的开发者账号，我这边没有。代价是你第一次打开会被系统拦一下，体验确实不如商业软件——这一点我认。
